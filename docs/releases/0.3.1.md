# PokGuy 0.3.1

[English](0.3.1.md) · [简体中文](0.3.1.zh-CN.md) · [Changelog](../../CHANGELOG.md)

Released 2026-11-09. This patch resolves the remaining dependency advisories and makes the repository easier to browse. Poker rules, saved-data keys and schema 2 are unchanged.

## Dependency fixes

- Upgrade to the supported vinext 1.0.1 / plugin-rsc 0.5.34 integration. It carries OG 1.0.3 and Satori 0.33.5 together with the upstream Node/Worker WASM and font fixes; React stays at 19.2.8.
- Scope minimatch 11.0.1 to typescript-eslint and fflate 0.7.5 to Satori. Remove the no-longer-needed image-size override. The locked dependency graph now reports **0 vulnerabilities** in the official-registry audit.
- Add a moderate-or-higher audit CI gate and real dependency regressions: parser matching, bounded adversarial globs, malformed ZIP64 rejection, decoded PNG rendering and unsafe SVG style rejection in built Node and Worker runtimes.
- Use the supported Vite development/build commands and explicitly preserve port 3000, with no silent port fallback.
- Make the showdown fixture guarantee the unique winner it asserts, avoiding false failures on legitimate split pots.
- Replace a fixed mobile scroll delay in browser checks with bounded layout assertions; preserve failure traces and screenshots in CI without weakening the viewport or touch-target requirements.

## A smaller repository home

- Reduce tracked root entries from **28 to 19**. Routes and Worker code live in `src/`, test configurations in `tests/`, and build helpers in `scripts/`. Prettier and PostCSS options live in `package.json`.
- Explicitly select the `src/` application root so an old checkout's leftover empty `app/` directory cannot hide the routes.
- Remove unused starter authentication code, three unused SVGs and the empty Next configuration. Required Vite/TypeScript/ESLint discovery files and hosting integration remain.
- Replace obsolete task-state/report copies with links to the fixed v0.3.0 archive. Git history and earlier release evidence remain available.
- Keep the English and Chinese home READMEs concise, each with one original training-table screenshot. Detailed walkthrough images remain in the user documentation.

## Upgrade and verification

Use Node 22, run `npm ci`, then `npm run dev`. Standard npm commands continue to work after the file moves. Export a full browser backup before clearing site data or changing the site's address. No storage migration or game-data reset is required.

See the [security assessment](../development/SECURITY_0.3.1.md), [acceptance record](../development/ACCEPTANCE_0.3.1.md) and [development commands](../development/README.md). Final PR and merged-main CI evidence are linked in the GitHub release.

This is a source release, not a production deployment. A zero audit result is a dated advisory-database result, not a claim that all software is vulnerability-free. Existing single-active-tab storage and physical-iOS verification limits remain.
